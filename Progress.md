# Universal Modem Progress

This file is an append-oriented engineering log. New work should add dated entries; earlier measurements and decisions should remain available for comparison.

## 2026-08-24 — Portable coded-OFDM foundation

Implemented the first required incremental layer as C11 with no third-party code dependencies:

- A 48 kHz, real-valued OFDM signal path with a fixed 256-point FFT (187.5 Hz carrier spacing), configurable carrier bounds, cyclic prefix, and overlap window.
- Gray-coded, unit-average-power QAM-4, QAM-16, and QAM-64 constellations with soft demodulation.
- Constraint-length-7 convolutional coding using the standard octal 171/133 polynomials, six termination bits, soft-decision Viterbi decoding, and punctured 1/2, 2/3, and 3/4 rates.
- Deterministic whole-block time/frequency interleaving so a contiguous acoustic cutout becomes dispersed erasures at the convolutional decoder.
- Self-synchronizing frames: an 8 ms swept-frequency sync waveform, quiet guard, two repeated channel-estimation symbols, per-symbol pilots, a fixed QAM-4/rate-1/2 protected header, and CRC-16/CRC-32 integrity checks.
- Channel normalization from the repeated training symbols. This supplies automatic gain handling and per-carrier complex equalization for quiet/loud signals and multipath within the cyclic prefix.
- A deterministic acoustic simulator supporting leading delay, attenuation/amplification, additive Gaussian noise, a delayed echo, clipping, and sample cutouts.

Default working configuration: bins 16–72 (3.0–13.5 kHz), 52 data carriers plus five pilots, QAM-16, rate-1/2 FEC, a 32-sample (0.667 ms) prefix, and an 8-sample (0.167 ms) overlap window. The conservative prefix and coding are discovery/data defaults only; calibration may select different values by direction.

Boundary leakage was measured using an oversampled FFT over a multi-symbol frame. With the same payload, rectangular symbol boundaries measured -20.96 dB out-of-band power and the 8-sample overlap window measured -23.66 dB. The window therefore remains enabled by default. High-quality calibration applies a small spectral-quality penalty to a zero-window candidate so an unrealistically flat simulated channel cannot select it solely for its few trailing samples.

## 2026-08-24 — Calibration

Implemented a real encode/channel/decode sweep rather than a formula-only selector. Every candidate logs its frequency range, QAM order, prefix duration, FEC rate, window, decode result, estimated SNR, EVM, payload rate, and score.

The default sweep tests 81 combinations: three useful bands, all three QAM modes, prefixes of 16/32/64 samples, and all three coding rates. With 32-byte probes and explicit 20 ms response/turnaround allowance, measured emitted-time estimates are 6.8 seconds per direction and 13.5 seconds for both directions. Handshake/configuration messages bring the intended live budget close to the roughly 15-second requirement.

`--calib-high` also sweeps ten bands, seven prefix lengths from 8–96 samples, and four overlap-window lengths. It tests 2,430 valid combinations and currently estimates 390 seconds for both directions, within the requested several-minute exploratory budget.

## 2026-08-24 — Asynchronous session simulation

Implemented a two-endpoint virtual acoustic session using the production modem frames for every wire message:

- The client periodically sends `DISCOVER`; the listening gateway sends `OFFER`; the client returns `CONFIRM`.
- Each direction calibrates independently and retains its own selected modem configuration.
- Data uses sequenced stop-and-wait delivery with acknowledgements, duplicate suppression, bounded retries, and direction-specific channel/configuration state.
- The simulator inserts a 2.8-second full acoustic blackout during transfer. After three timeouts both endpoints return to discovery, tolerate discovery attempts made during the outage, reconnect, and resume without duplicating delivered bytes.
- Transmit/listen turnarounds are explicitly scheduled (60 ms negotiation and 25 ms data/ACK), so endpoints do not listen to their own output or transmit simultaneously in the validated protocol flow.

The default simulation transferred 3,072 bytes client-to-gateway and 1,536 bytes gateway-to-client, incurred three data retries, re-established the connection once, and finished connected in 20.92 seconds of virtual time.

## 2026-08-24 — Progressive distortion-to-failure validation

Replaced the calibration and asynchronous-session single-point channel checks with a shared eight-level distortion ladder. Each runner now starts with a genuinely clean channel and cumulatively introduces:

1. asymmetric quiet/loud gain and capture delay;
2. multipath echo and increasing echo delay;
3. additive Gaussian noise;
4. nonlinear clipping, an in-frame sample cutout, and a timed total-link blackout;
5. increasingly severe combinations of all those impairments;
6. a terminal no-usable-signal profile that guarantees a measured failure boundary.

The two directions deliberately use different levels to model asymmetric microphones, speakers, and room paths. Every pass logs all exact channel values. A passing combined-impairment level must exercise gain extremes, leading delay, echo, noise, clipping, sample loss, and—in the session runner—a full outage before the ladder is allowed to count the coverage as complete.

It falls through to slower/more robust candidates when a fast candidate is not repeatable. ## 2026-08-24 — Native real-audio connection and transfer phase

Implemented the hardware-facing audio phase without enabling TUN/utun, route, forwarding, or NAT changes. The executable now has native system backends for ALSA on Linux and CoreAudio/Audio Queue Services on macOS. Both use 48 kHz mono signed 16-bit PCM at the device boundary and convert to the modem's floating-point sample representation internally. Linux links only the system ALSA library; macOS links only the bundled CoreAudio, AudioToolbox, and CoreFoundation frameworks.

Every real-audio startup enumerates input and output devices before opening either one, prints stable device IDs and descriptions, and then prints the exact selected input/output IDs. `--list-audio` performs enumeration without starting a session. Devices can be selected independently with `--input-device ID` and `--output-device ID`; `default` remains the default for each. CLI logs are explicitly flushed so state remains visible immediately even when redirected to a file.

The real link uses a versioned binary wire envelope inside the existing CRC-protected coded-OFDM frame. It implements `DISCOVER`, `OFFER`, `CONFIRM`, and `CONNECTED` negotiation; typed calibration control/probe/report/verification messages; test-data frames and robust bootstrap-mode ACKs; transfer turns; and completion. Session IDs reject unrelated traffic. The client repeats discovery every two seconds by default, while the gateway listens indefinitely. A signal loss, failed verification, exhausted data retry, or malformed link frame returns both roles to discovery/listening and starts a fresh session rather than continuing with stale configuration.

Audio operation is explicitly half duplex. Capture is dropped/paused before every playback operation, output is fully drained, a 50 ms quiet tail is included for acoustic decay, and capture is restarted and flushed afterward. An additional 80 ms protocol turnaround is reserved before replies so the peer has time to drain its speaker and resume its microphone. CoreAudio waits for the queue's actual stopped state rather than treating a reusable playback buffer as proof that the speaker has finished.

Real calibration is independent in each direction. The default live design uses a balanced 27-point fractional sweep across all three frequency ranges, QAM-4/16/64, 16/32/64-sample prefixes, and all three FEC rates. At 220 ms per deterministic slot this schedules 5.94 seconds of probes per direction, or 11.88 seconds total; handshakes, selection reports, and three independent 128-byte verification frames put the intended wall time near the roughly 15-second target. `--calib-high` uses 810 valid balanced candidates across ten ranges, seven prefix lengths, four overlap windows, all QAM modes, and all FEC rates: 178.2 seconds of probes per direction and roughly six minutes total before control overhead. Every attempted configuration logs its complete parameters and its decode result; successful receives also log SNR, EVM, and throughput score. The highest-scoring candidate must then pass all three independent verification frames. Each direction communicates its own calibration mode, so peers with different local `--calib-high` choices can still interoperate.

After calibration, the client initiates a deterministic test transfer in both directions. Defaults are 1,024 bytes each way in 128-byte chunks. Data runs on the independently selected directional mode; ACK and control messages remain on the robust QAM-4/rate-1/2 bootstrap mode. Stop-and-wait delivery provides bounded retransmission and duplicate suppression. The receiver verifies every generated byte, while progress logs report bytes, effective bit rate, sequence, sync correlation, estimated SNR, and EVM. `--test-bytes`, `--chunk-bytes` (up to 512), and `--retries` make the physical test easy to shorten or expand.

Build and inspect devices with:

```sh
make
./universal-modem --list-audio
```

For this phase, run without `sudo` unless the local audio setup specifically requires it; no privileged network state is touched. On the two systems, use IDs printed at startup if `default` is not correct:

```sh
./universal-modem --audio --gateway --input-device INPUT_ID --output-device OUTPUT_ID
./universal-modem --audio --client  --input-device INPUT_ID --output-device OUTPUT_ID
```

## 2026-08-24 — Recorded-room receiver and calibration redesign

Analyzed `client_connection_request_recorded.wav` as a real cross-machine capture before changing the PHY. The file is 44.1 kHz mono signed-32 PCM and must be resampled to the modem's 48 kHz rate for valid timing. Its active signal is roughly -30 dBFS with a -54 dBFS pre-signal noise floor and no ADC clipping. The old 8 ms chirp still correlates at 0.72 after correct resampling, but its response falls sharply above 10 kHz: quarter-band correlations measured 0.87, 0.88, 0.62, and 0.22 from low to high. The two old training repeats provide about 12.3 dB aggregate SNR, the carrier response spans 17.7 dB, 17 of 49 carriers are below 10 dB, and three are below 0 dB. The first training symbol is approximately 5 dB more contaminated than the second. Measured acoustic energy remains 10–15 dB over the noise floor 10–20 ms after transmission and reaches the floor only around 52 ms. These measurements explain why the short 2 ms sync gap, 0.33–1.33 ms calibration prefixes, unweighted zero forcing, and wall-clock calibration slots could connect marginally but could not calibrate.

The receive front end is now explicitly amplitude invariant rather than assuming that quiet input should always receive more gain. Each capture has DC removed and is normalized from its strongest 5.3 ms RMS block to a fixed floating-point working level, with bounded scaling for numerical safety. The original active RMS, peak, normalization multiplier, and full-scale clipping fraction are retained in receive metrics and emitted in connection, calibration, failure, and data logs. Regression frames decode at 0.0001x, 0.35x, and near-full-scale 1.10x input levels with substantial DC offsets. Normalization handles quiet and loud recordings consistently; clipping remains separately visible because scaling cannot restore samples already flattened by an ADC.

Replaced the 256-point room-inappropriate OFDM geometry with a 2,048-point FFT (23.4375 Hz carrier spacing). Calibrated data uses a 1,024-sample acquisition chirp, 2,048-sample acoustic settling gap, three training symbols, and a default 768-sample/16 ms cyclic prefix. Robust discovery/control uses a 2,048-sample chirp, 3,072-sample/64 ms settling gap, four training symbols, a 1,024-sample/21.33 ms prefix, QAM-4, rate-1/2 FEC, and the measured-strong 1.5–10.5 kHz band. The chirp itself now uses 1.5–11.5 kHz, avoids the recorded weak high band, has substantially greater processing gain, and uses a short edge taper rather than a full Hann attenuation.

Acquisition now uses an FFT matched filter with sliding, mean-free normalized correlation, a normalization-aware silence floor, and a length-dependent false-alarm threshold. Once the strongest path is found, the receiver searches backward by one cyclic prefix for an earlier usable path so a loud reflection does not move the OFDM origin past the direct arrival. This is covered with a test whose first reflection is stronger than its direct path.

Channel recovery now averages three or four repeated training symbols, estimates and smooths per-carrier noise, and converts carrier SNR into soft-bit reliability so deep fades become low-confidence evidence instead of large zero-forcing errors. Per-symbol pilots normalize amplitude, fit common phase, and conditionally fit a bounded phase slope only when it materially improves pilot coherence; this tracks sample-clock/timing drift without overfitting noise. A low-crest-factor quadratic-phase training multitone keeps the measured training crest factor at 1.87 with 0.418 RMS.

The transmitter previously generated a 5.42-times-full-scale OFDM peak, which both native backends silently clipped before playback. Symbols are now peak-normalized, pilot amplitude removes the resulting symbol-to-symbol scale at the receiver, and the completed overlap-added OFDM region receives a final 0.90-full-scale ceiling. The deterministic regression frame now peaks at 0.780 with zero full-scale overflows. Its 64-sample boundary window measures -28.78 dB out-of-band energy versus -27.06 dB for rectangular boundaries.

Real calibration no longer assumes two independent machines share 220 ms wall-clock slots. The receiver sends an individually sequenced `CALIB_READY` before every probe; a failed candidate therefore cannot shift all subsequent probes onto the wrong configuration. The default primary sweep is a nine-run, three-level orthogonal design. It covers every pair of low/mid/high frequency range, QAM-4/16/64, 8/16/21.33 ms prefix, and 1/2, 2/3, 3/4 FEC exactly once. The bands vary both endpoints: 1.125–8.484, 1.5–11.484, and 3–15 kHz. A shorter but still coded and room-settled control mode keeps the measured receiver-synchronized primary sweep at 8.6 seconds per direction. `--calib-high` uniformly samples 94 points from the larger ten-band, seven-prefix, four-window grid for a several-minute diagnostic sweep.

The receiver retains the five highest-throughput successful candidates. Each is tested with three independently generated 128-byte frames; if an optimistic mode fails, both peers advance to the next ranked mode instead of discarding the entire connection. This also fixed a concrete live bug where verification trials two and three derived their expected data from the prior one-byte result message rather than the selected candidate index. Damaged control frames are ignored until their receive deadline instead of aborting immediately, and failed calibration frames receive extra acoustic settling time before the receiver transmits again.

The hardware-independent suite now passes 17 test groups. New coverage includes quiet/nominal/loud normalization, zero transmit clipping, low-crest training energy, a 1,024-byte room channel with five taps through 15.23 ms, a reflection stronger than the direct path, additive background noise, and 200 ppm independent sample-clock error. The complete calibration and asynchronous session distortion ladders now pass through level 5 and first fail at level 6. `make test` is warning-free, and the final AddressSanitizer/UndefinedBehaviorSanitizer build passes all 17 groups. The ALSA `null` lifecycle still opens, lists devices, enters listening, and interrupts cleanly. ## 2026-08-24 — Real calibration gate and v2-worse full-session validation

EVM now represents the signal actually consumed by the decoder. Physical symbol repetitions are independently pilot-corrected and combined first; constellation error is then measured on the combined symbol and weighted by the same carrier reliability, pilot coherence, and symbol evidence used for soft FEC input. Deep-fade carriers that contribute almost no decoding evidence therefore no longer dominate the reported quality number. Successful frames report payload-mode EVM instead of averaging their always-QPSK header into a higher-order payload result. The permanent low-level regression's effective EVM changed from 0.265 to 0.194 without altering its exact 128-byte result.

The robust baseline now has a deliberately different proof rule from bandwidth upgrades. Its primary frame must decode exactly, have synchronization correlation of at least 0.30, and have at least 6 dB measured training SNR. It must subsequently decode all three independent 128-byte verification frames exactly with the same acquisition margin. Decision-directed EVM remains visible as a diagnostic, but cannot veto this repeatedly demonstrated rate-1/2, repeated-QPSK path. ## 2026-08-25 — Adaptive calibration and half-duplex handoff correction

The next two-machine log isolated a half-duplex timing failure rather than a reverse-path PHY failure. The Mac had just decoded `OFFER` and `CONNECTED` from the gateway with synchronization correlations near 0.7, but the first gateway-to-client calibration baseline fell to 0.080. `CALIB_READY` could be decoded before its sender had finished the 50 ms output tail and restarted capture. The peer transmitted the requested probe immediately, so its 20 ms leading guard and part of its 42.7 ms synchronization waveform arrived while the receiver microphone was still paused or before CoreAudio capture callbacks had resumed. The existing 160 ms calibration delay occurred before `READY`, on the wrong side of the exchange. The transmitter now waits an explicit 120 ms receiver-arm interval after decoding every `READY` before playing the probe.

The paired audio test previously made this race impossible: it inserted the entire impaired waveform into the peer queue atomically and made capture restart instantaneous. Its fake backend now holds capture unavailable for 60 ms after every restart. With the old protocol this reproduced the hardware symptom: connection and the complete first-direction calibration succeeded, the first reverse probe was missed, both peers timed out, and the session reconnected. The post-`READY` arm interval makes that same test complete without a timeout. Ordinary handshake, ACK, and data turnarounds are exercised under the same delayed restart.

Replaced the fixed 10/95-entry table with a receiver-driven adaptive search. Default and high-quality modes now have maximum budgets of 12 and 64 probes, respectively, rather than a mandatory count. The exact 17-byte modem configuration and the reason for trying it are carried in each CRC-protected `CALIB_READY`; ranked reports also carry complete configurations. The transmitting peer therefore follows the receiver's measured search decisions and no longer has to independently reproduce a fixed candidate index table.

The search starts with the non-negotiable repeated-QAM-4/rate-1/2 baseline. A passing configuration generates neighbors that change exactly one parameter: physical repetition count, QAM-4 to QAM-16 to QAM-64, FEC rate, cyclic prefix, upper band edge, lower band edge, or training length. High-quality mode additionally explores acquisition length, settling gap, cleaner narrowed bands, overlap window, and upper frequencies through 18 kHz. Each major dimension receives an initial experiment before the remaining budget is spent best-first on the highest predicted 128-byte effective payload rate. Only passing parents can generate descendants; a failed or marginal result terminates that branch. If every immediate default upgrade fails, the frontier ends after eight total probes instead of spending the full budget on unrelated compound configurations.

Selection now scores actual framed payload rate, including synchronization, settling, training, header, prefix, repetition, QAM, and FEC overhead, then applies the measured quality penalty. The five best passing modes are ranked, the proven baseline is retained as the final fallback, and the selected mode must still pass three independent exact 128-byte verification frames. Both the simulated and live calibrators use the same adaptive search implementation.

New search regressions prove that every proposal differs from a previously passing parent by exactly one field, rejected nodes never produce children, exhausted frontiers stop early, default/high budgets are bounded, all QAM and coding levels remain reachable, and all required default dimensions are explored. ## 2026-08-25 — Log-guided default and outcome-directed calibration search

The first successful two-machine `--calib-high` run showed a strongly asymmetric but consistent channel. QAM-16 was repeatedly marginal or failed in both directions, while QAM-4 remained productive. The gateway-to-client direction successfully progressed through rate-3/4 coding, an upper edge of 18 kHz, a 128-sample prefix, and a 32-sample overlap window. The noisier client-to-gateway direction produced many one-frame successes from similarly aggressive modes, but its four highest-ranked modes all failed the first independent 128-byte verification frame and it ultimately selected the repeated robust baseline. The primary search had used only a 16-byte payload, so it was too optimistic relative to both verification and the default 128-byte data chunk. It also spent too much of its budget retrying QAM-16 in slightly different surrounding configurations.

Primary calibration probes now carry 128 deterministic bytes in both the real and simulated paths. A primary PASS therefore demonstrates one complete normal-sized data frame before a mode can enter the verification ranking. The maximum searched frame is 1.265 seconds and remains inside the three-second live receive deadline. The all-pass default search emits approximately 14 seconds of primary audio across both directions, while high mode retains its larger diagnostic budget.

The conservative discovery/control baseline is unchanged. The ordinary data default is now a grounded second probe derived from the real log: QAM-4, rate-2/3 FEC, one repetition, a 1.5–8.484 kHz band, a 1,024-sample prefix, a 64-sample overlap window, three training symbols, a 1,536-sample synchronization chirp, and a 2,560-sample settling gap. This gives calibration a plausible multi-parameter starting point immediately after the baseline rather than requiring the same combination to be rediscovered one mutation at a time. A failed grounded probe does not prune the baseline's independent one-parameter alternatives.

The adaptive frontier now learns separate pass/fail histories for each change type and target value. Candidate priority combines complete 128-byte framed payload rate with observed success, modest one-time exploration bonuses, and a continuation bonus for taking another step in a direction that just worked. Productive QAM-4 bandwidth, FEC, and prefix branches are therefore explored more deeply. Repeatedly failing QAM, repetition, low-band, or narrowed-band targets are suppressed quickly; FEC and prefix changes receive more evidence before suppression because their useful boundary is likely gradual. Applying the same already-proven target value across many neighboring configurations is penalized to prevent combinatorial duplication. High mode still explicitly reaches synchronization, settling-gap, overlap-window, 18 kHz upper-band, and 128-sample-prefix experiments when the channel supports them.

Ranked verification now forms a progressive fallback ladder from the highest-scoring candidate through its successful direct ancestors, then fills any remaining slots with other viable modes and always reserves the robust baseline last. Thus, if an aggressive compound mode fails verification, the next trial removes one demonstrated optimization instead of jumping among several equally aggressive near-duplicates and then directly to the bootstrap. Live logs summarize pass/attempt counts for the important search directions and explicitly report when QAM upgrades produced no pass and were deprioritized.

Calibration currently sweeps the cyclic prefix from 1,024 down through 896, 768, 640, 512, 384, 256, and 128 samples (21.333 to 2.667 ms); it does not yet sweep FFT size or carrier spacing. ## 2026-08-25 — Reliability review, efficient search, and persistent calibration

The latest successful two-machine high-calibration log exposed three remaining reliability gaps. A mode that merely resembled the robust bootstrap could inherit its permissive CRC/synchronization gate, three successful verification frames could still be followed by a sustained data-frame failure, and the search could spend most of its bounded budget reapplying the same successful mutation while leaving an independent coding or bandwidth direction unmeasured. The old 192-node frontier also ended exactly at candidate ID 191 in the real run, and reducing the overlap window from 64 to 32 or zero samples provided essentially no 128-byte frame-rate benefit while weakening spectral tapering.

The permissive gate is now limited to the exact robust geometry, allowing only an increased physical repetition count. Every optimized QPSK configuration must meet the normal SNR/EVM margin; its rate-1/2 allowance is now 8 dB and 0.42 EVM instead of the former 6 dB and 0.462 EVM. Ordinary calibration still verifies three full 128-byte frames, while `--calib-high` now verifies five. If the two-repeat baseline itself cannot decode with margin, calibration automatically tries otherwise identical three- and four-repeat modes before declaring the direction unusable. Primary and verification receive deadlines were extended to four seconds so these deliberately slower recovery modes fit without a false timeout.

Adaptive search now measures every available independent speed axis once before deepening the branches that work. It proposes a change only when it improves the actual framed 128-byte probe rate by more than 0.5 bit/s, can skip a quantized QAM/FEC/band value that changes no frame duration, tries a successful target value in at most two surrounding configurations, and stops a repeatedly failing QAM target after two attempts. The high search still follows productive FEC, upper-band, prefix, sync, gap, and training directions, but no longer burns probes rediscovering the same result. The bounded node frontier was raised from 192 to 512 without raising the 12/64 transmitted-probe budgets. Fixed safe windows of 96 samples for bootstrap and 64 for ordinary data replace the obsolete window calibration dimension, including removal of the zero-window scoring path. In the all-pass search regression, default uses its 12 probes across every core rate axis and high naturally stops after 45 useful probes; a QAM-rejecting channel uses exactly two QAM probes while still reaching a 15 kHz/640-bin upper edge and a 128-sample prefix in 42 total probes.

Stop-and-wait data ACKs now use the independently calibrated reverse-direction mode instead of always using the slow bootstrap. A short ACK is therefore carried by a mode that already passed full-size directional verification, improving effective transfer rate without assuming the two acoustic directions are symmetric. Data receive deadlines are four seconds so verified three/four-repeat recovery modes remain usable.

Real-audio startup now reads `calibration.config`, a strict plain-text, receiver-owned cache. It records the format and live-protocol versions, role and receive direction, FFT and band bins, cyclic prefix, overlap window, synchronization and settling lengths, training and physical repetition counts, QAM, and FEC. Writes go through `calibration.config.tmp` and an atomic rename. Missing, malformed, wrong-role, or incompatible-version files are logged and ignored; a valid file is logged with its complete mode and skips that machine's inbound calibration. The client and gateway exchange cached/missing status immediately after connection, so two caches skip both directions, no caches calibrate both directions, and exactly one missing cache calibrates only the corresponding receiver direction. A newly measured local direction is saved immediately and is retained in memory even if the file write fails. Both cache files are machine-specific runtime state and are ignored by Git; deleting the local file intentionally requests recalibration on the next startup.

The cache exchange and modem-config wire encoding are protected by an explicit capability handshake. Live protocol version 3 advertises protocol, config format, and 128-byte calibration-probe size in DISCOVER/OFFER/CONFIRM/CONNECTED. A mixed build now stops with a clear rebuild-both-machines diagnostic instead of silently interpreting a different calibration sequence or frame body.

Every scenario completes 256 bytes in each direction with no final reconnect.

## 2026-08-25 — TUN/utun Internet proxy and explicit link-test mode

Normal client and gateway operation now enters the real-audio network proxy without requiring `--audio`; the flag remains accepted as an explicit medium selection. The former finite 1,024-byte transfer remains available as `--link-test`, and that mode explicitly does not create a network interface or alter routes, DNS, forwarding, or firewall state. Live protocol version 4 includes this mode in DISCOVER/OFFER/CONFIRM/CONNECTED capability negotiation, so peers cannot accidentally run a link test against a network proxy. Both machines must again run the same rebuilt binary.

Added one native network abstraction with separate Linux and macOS implementations. Linux opens `/dev/net/tun`, requests a dynamically named layer-3 interface with `TUNSETIFF` and `IFF_TUN | IFF_NO_PI`, assigns the point-to-point `10.77.0.1`/`10.77.0.2` addresses, and sets a 576-byte MTU. The client installs the two more-specific IPv4 default halves through the TUN and publishes per-link catch-all DNS through `resolvectl` when available. The gateway discovers its existing default egress, preserves and enables IPv4 forwarding, and installs process-tagged MASQUERADE and stateful forwarding rules with iptables or a uniquely owned nftables table. Cleanup removes only the routes, DNS state, firewall objects, and forwarding change created by this process.

macOS opens a dynamically assigned utun through the public kernel-control interface (`PF_SYSTEM`, `SYSPROTO_CONTROL`, `CTLIOCGINFO`, and `UTUN_CONTROL_NAME`), obtains its assigned name with `UTUN_OPT_IFNAME`, and handles the utun four-byte network-order address-family prefix. It configures the same point-to-point addresses and split IPv4 default route. Client DNS is published as a catch-all supplemental resolver through a held `SCDynamicStore` session. The gateway preserves and enables `net.inet.ip.forwarding`, loads NAT/state rules into a process-specific `com.apple/universal-modem-*` PF anchor, and owns a `pfctl -E` reference token so cleanup can flush only that anchor and release only its reference. The Darwin target now links SystemConfiguration in addition to the existing CoreAudio frameworks.

IP transport runs only after both directional calibration modes are available, whether measured or loaded from each machine's existing `calibration.config`. The client opens the proxy with a versioned MTU/chunk negotiation, then initially owns a half-duplex token. Complete IPv4 or IPv6 packets are length-validated, divided into CRC-protected fragments, and reassembled exactly before being written to the peer interface. Each fragment uses stop-and-wait acknowledgement in the independently calibrated reverse direction. Lost fragment ACKs cause exact duplicate re-ACK rather than duplicate packet injection, including after the 16-bit fragment sequence wraps. A bounded two-packet burst and 350 ms idle turn keep either direction from monopolizing the acoustic channel.

Token transfer is a three-phase `TURN`/`TURN_ACK`/`TURN_COMMIT` exchange. A repeated TURN reissues its ACK, and a repeated ACK after a lost commit makes the prior owner resend the commit. Consequently neither side can believe it owns the half-duplex channel merely because the final control frame was lost. Acoustic failure returns both sides to discovery/listening, discards the suspect in-memory modes so the next connection recalibrates, and keeps an already configured TUN/utun alive so queued system traffic can resume after reconnection. Signal or normal process exit removes the complete network configuration.

The independent paired-live backend now supplies actual valid IP datagrams through separate fake client and gateway network devices. Its worse-than-recorded-v2 asymmetric acoustic run performs discovery, two adaptive calibrations, verification fallback, and exact fragmented delivery of a maximum-MTU 576-byte client packet plus a 413-byte gateway response. The same connection deliberately drops the gateway proxy-start ACK, the first IP-fragment ACK, the first token ACK, and the first token commit; all four recover without reconnecting or duplicating a packet. Separate runs retain the explicit bidirectional link test, both-cache skip, one-sided missing-cache calibration, and severe-channel robust fallback.

The final optimized suite passes all 22 modem/channel/session groups and all four asynchronous paired-live scenarios. A full warnings-as-errors build passes. AddressSanitizer and UndefinedBehaviorSanitizer pass the complete suite, and the affected live suite was rerun under both sanitizers after the sequence-wrap correction. Default CLI startup was exercised without `--audio` and reports `mode=network-proxy`; `--link-test` reports its no-network guarantee. The macOS-specific source also passed an isolated Clang warnings-as-errors syntax check against the corresponding public SDK declarations. `git diff --check` passes and `README.md` remains unchanged. This managed Linux environment is unprivileged and has no `/dev/net/tun`, so privileged kernel interface, route, DNS, NAT, and real two-machine packet-flow validation remains the immediate hardware test rather than a claimed local result.

## 2026-08-25 — Native macOS feature-namespace correction

The first native Xcode SDK build exposed a limitation in the earlier synthetic Darwin-header check. `network.c` globally defined `_POSIX_C_SOURCE=200809L`; Apple's `sys/cdefs.h` treats that as the strict POSIX compilation environment and consequently hid the Darwin/BSD declarations required by the same SDK's networking headers. This produced undeclared `u_int`, `u_short`, `IFNAMSIZ`, and `AF_SYSTEM` errors before any network implementation code compiled. Feature selection is now platform-specific: macOS defines `_DARWIN_C_SOURCE`, while Linux retains `_DEFAULT_SOURCE` plus `_POSIX_C_SOURCE=200809L`. This requests Apple's documented full Darwin namespace instead of locally redefining SDK types or constants. The complete warnings-as-errors build, all 22 modem/session tests, and all four paired-live scenarios pass after the correction; the ordinary optimized binary was restored. A native macOS rebuild is still the authoritative confirmation because this Linux host does not contain the Xcode SDK.
